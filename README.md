# ADMT — автономное приложение для водоискателя

Приложение для работы с приборами Aidu серии S (ADMT-100S и родственные)
без зависимости от оригинального приложения производителя.

Собирается под 64-битные процессоры, поэтому работает в том числе на
Poco X7 Pro и других телефонах на Dimensity 8400 и новее.

## Что умеет

- связь с прибором по Bluetooth (классический SPP)
- рукопожатие, чтение заряда батареи, модели и метода опроса
- замер точки профиля, повтор и принудительное чтение
- хранение профилей на телефоне, удаление ошибочных точек
- разрез с изолиниями, сглаживание по глубине, логарифмическая шкала
- автоматический поиск зон пониженных значений с указанием доли от фона
- трёхмерный вид по нескольким параллельным линиям
- выгрузка в CSV, XYZ (Surfer/Voxler) и JSON формата Aidu

Графика работает офлайн: библиотека Plotly лежит внутри приложения,
интернет не нужен.

## Откуда взялся протокол

Восстановлен из приложения Aidu Prospecting 2.11.10, пакет
`com.aidush.app.measurecontrol.bluetooth`.

Кадр запроса:

```
AA | model | sampleMethod | 55 | len | cmd | params... | CS
len = длина params + 2
CS  = (len + cmd + сумма params) & 0xFF
```

Кадр ответа:

```
55 | model | sampleMethod | AA | len (2 байта) | cmd | data[len-2] | CS
```

Команды: `0x10` рукопожатие, `0x20` батарея, `0x30/0x32` время,
`0x40/0x42` модель, `0x50` частоты, `0x52/0x54` метод опроса,
`0x60` замер, `0x62` принудительно, `0x64` повтор, `0x66` офлайн,
`0x68/0x70` файлы в памяти прибора.

Ответ `0x63` — подряд идущие 4-байтовые числа с плавающей точкой
(порядок байт little-endian), по одному на каждый уровень глубины.
Для ADMT-100S это 20 значений.

### Единственное тёмное место

В коде Aidu два байта длины в ответе читаются противоречиво: приёмный
автомат считает их little-endian, разборщик кадра — big-endian. Что реально
идёт по проводу, из кода не выводится.

Поэтому `FrameReader` определяет порядок сам: первые кадры разбираются в
обоих вариантах, принимается тот, у которого сходится контрольная сумма.
Дальше найденный порядок запоминается. Логика проверена на синтетических
кадрах обоих типов — оба разбираются верно.

## Сборка: путь А, Android Studio

1. Установить Android Studio (последнюю версию).
2. `File → Open`, выбрать папку проекта.
3. Дождаться загрузки зависимостей.
4. `Build → Build Bundle(s) / APK(s) → Build APK(s)`.
5. Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.

## Сборка: путь Б, без компьютера

1. Создать репозиторий на GitHub (можно приватный).
2. Загрузить туда содержимое этой папки, включая `.github/workflows/build.yml`.
3. Открыть вкладку `Actions` — сборка запустится сама.
4. Через несколько минут скачать `admt-apk` из раздела Artifacts.

## Установка

APK не подписан ключом магазина, поэтому при установке телефон спросит
разрешение на установку из неизвестного источника.

## Первый запуск

1. Сопрягите прибор в системных настройках Bluetooth (это делается один раз).
2. Вкладка «Прибор» → выберите прибор → «Связь».
3. Дождитесь надписи «Прибор на связи» и показаний заряда.
4. Вкладка «Замер» → создайте профиль → «Замерить точку».

Если связь встала, а замер не приходит — откройте журнал обмена на вкладке
«Прибор». Там видны отправленные и принятые кадры в шестнадцатеричном виде.
Эти строки и нужны для разбора любой нестыковки.

## Чего приложение не делает и делать не может

Цвет на разрезе показывает относительный контраст измеренной величины
вдоль профиля. Это не сопротивление в Ом·м и не вода.

Шкала глубин условна: диапазон прибора делится на число уровней, как это
делает и оригинальное приложение. Расчёта глубины проникновения через
скин-слой здесь нет — его нет и у производителя.

Одноканальный магнитотеллурический метод неоднозначен по своей природе:
тонкий проводящий слой и толстый умеренно проводящий дают почти одинаковый
отклик на поверхности. Никакая обработка это не разделяет.

Решение о бурении принимается по совокупности: несколько профилей,
повторные замеры, привязка к геологии и соседним скважинам.
